从逐条预测看，主要问题是：**这次增加了很多同一实体的边界变体，却没有稳定增加新的正确实体；同时，位置定位错误和请求失败又抵消了一部分召回收益。** ncbi 上这个问题最突出。

下面只比较相同模型 GPT-5.6-sol，并把失败样本按空预测计入：

| 数据集 | 正确预测数：baseline → 本次 | 误报数：baseline → 本次 | 新找对的实体 | 丢失的原有正确实体 |
|---|---:|---:|---:|---:|
| bc2gm | 312 → 318 | 180 → 242 | 73 | 67 |
| bc5cdr | 881 → 935 | 196 → 260 | 82 | 28 |
| ncbi | 325 → 323 | 53 → 173 | 21 | 23 |

这解释了为什么 P 普遍下降、R 提升有限：新增正确预测不足以抵消误报增长，而且本次是重新生成预测，未必保留 baseline 已经识别正确的实体。

**1. 提示词鼓励的行为，与精确边界评分存在冲突。**

当前 [提示词](/Users/tuenglee/Desktop/bioAgent/MyBioAgent/tool.py:7) 明确要求：

> favor recall；Allow overlaps and alternative boundaries

在 ncbi 的一个实际样本中，标准答案包含 `myopathy`，本次却同时输出：

- `late onset progressive myopathy`
- `progressive myopathy`
- `myopathy`

这三个候选只贡献一个正确预测，另外两个都算误报。类似的还有同时输出 `breast - ovarian cancer` 和内部的 `ovarian cancer`。

ncbi 中，与标准实体区间重叠的误报从 **33 增到 129**。总误报净增 120 个，其中这一类净增 96 个，占 **80%**。因此，边界扩张和拆分是最主要的可见问题，不能简单理解为模型完全不认识疾病。

**2. “多列候选”没有转化为有效的召回增加。**

ncbi 相比 baseline 新增了 **149 个不同的预测位置，其中只有 21 个正确，约占 14.1%**。与此同时，还丢失了原来正确的 23 个实体。

例如，一个样本的标准答案包含 `MEN1` 和 `MEN2`，baseline 都识别出来了；本次却只输出泛称 `disease`。另一些样本输出了未被标注为疾病的 `BRCA1 mutations`、`severe disease`。

这说明模型扩大了“可能与疾病有关”的范围，但没有更准确地掌握当前数据集的标注边界。**关联疾病的表达，不一定就是该位置应标注的疾病实体。**

**3. 新的 `occurrence_index` 定位方式也制造了错误。**

我确认了两个具体例子：

- `parathyroid tumor` 在句中只出现一次，模型却返回 `occurrence_index: 1`，导致正确的实体文本无法定位。
- 同一句先出现 `WASP`，后出现独立的 `WAS`。模型返回 `WAS`、索引 0，而代码按子字符串查找，把它定位到 `WASP` 内部，造成一次误报和一次漏报。

因此，部分 R 损失发生在“文本已经识别出来、位置却映射错了”这一步。[定位代码](/Users/tuenglee/Desktop/bioAgent/MyBioAgent/tool.py:34) 的影响需要与提示词问题分开看。此前统一 API 失败处理后，两个流程仍存在这些后处理差异。

**4. bc2gm 的收益还被请求失败严重抵消。**

bc2gm GPT 有 **91 条请求失败**；这些样本上，baseline 原本识别正确的实体有 **63 个**。本次丢失的 67 个原有正确实体中，63 个位于失败样本。

所以三个数据集的情况并不完全相同：

- **bc2gm：** 请求失败是召回收益被抵消的主要因素，同时误报增加。
- **bc5cdr：** 确实多找对了不少实体，但误报也增加，形成“R 上升、P 下降、F1 小幅改善”。
- **ncbi：** 没有 API 失败，主要是重复边界、额外疾病相关表达和定位错误；有效召回没有增加，P 明显下降。

如果把它定位为“候选发现 agent”，P 下降可以接受，但应换来明显的候选覆盖率提升。**目前 ncbi 连这一点也没有达到**，不能仅用“后面还有过滤 agent”解释。下一步最值得验证的是：单独去掉“允许替代边界”的要求、单独检查实体定位，再用同一批样本观察各自对 P/R 的影响。这需要消融试验才能区分贡献；当前逐条结果已经给出了明确的排查方向。
